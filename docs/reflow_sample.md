# 投递回流校准报告（真实中文 JD · 脱敏样例）

> 口径：**终局录取（有没有拿到 offer）**　｜　正反馈 = 只有拿到 offer（进面试但淘汰是中间态，单列）

> 匹配分来源：你的经历 × 各条 JD 原文（规则引擎，无模型 API）

## 2. 校准：预测匹配分 ↔ 真实结果

- 参与相关系数计算的样本：**50**（总记录 50，其中 0 条没有 JD 原文，无法算预测分）
- 整体正反馈率：0.14
- **Pearson r = 0.003**

> 匹配分和真实结果几乎无关（|r| < 0.15）。说明现在的匹配模型基本在猜——它打的高分没有转化为更多面试，下一步应该降低对它的信任，转去收集更多真实结果反推权重。

### r 低的时候，先看分布再下结论

- 预测分区间：0 ~ 70（跨度 70 分），全部 50 条中位 25 分
- **正反馈组中位分 14** vs **非正反馈组中位分 25**

> 正反馈组中位分反而比非正反馈组低 11 分，方向是反的。两种可能：① 引擎打分口径有问题（该给高分的岗位没给）；② 这批结果本身与岗位契合度无关（换个更强的打分器也一样）。**先看下面的逐条明细里那些「低分却拿到 offer」的岗位**——如果它们明显是些门槛不高的岗位，那就是 ②。

> 这一步很重要：**r ≈ 0 有两种完全不同的成因**——① 引擎打分没有区分度（它该给高分的没给）；② 结果与岗位契合度本来就无关（数据里就是这样，换个更强的模型也一样）。看正负两组的分数分布重叠不重叠，才能判断该修引擎还是该认这个数据。

## 7. 边界（必须说清）

- **匹配分不是录取概率。** 这里的 r 只回答「匹配分能不能预测这个口径下的正反馈」，不代表对任意人、任意岗位都成立。
- 归因靠回流备注的关键词分类，是**启发式**；备注是事后描述，可能有偏差。
- 只有拿到 offer 才算正反馈，样本量小、offer 率低时 r 的置信区间很宽，n<30 基本只能当方向性参考。
