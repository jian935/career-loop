## 1. 作品标题
**career-loop · 先别投，先看清你差在哪**

## 2. 一句话简介
一个可证伪的求职匹配工具：粘贴 JD 和经历，10 秒得到匹配分、逐项缺口，再用你真实的投递结果回算「这个分数到底准不准」。纯前端、数据不上传。

## 5. 详细介绍（用于表单「作品说明」）
career-loop 面向所有岗位求职者（尤其应届生），解决一个真实痛点：**投简历像盲投**——
同一个「我会 Python / 我做过 Agent」在不同 JD 里含金量完全不同，而你永远不知道上次说自己很匹配的
工具，到底有没有帮你拿到面试。

它把「我到底适不适合这个岗位」从玄学变成**可证伪、可校准的数据闭环**：
1. 把 JD 拆成能力项，逐条与你的经历比对，给出带原文证据的匹配矩阵与加权匹配分；
2. 告诉你**补哪一项能力分数涨最多**（反事实），以及一批岗位里**先投哪个**；
3. 你拿它去投递，再把真实结果（已读 / 面试 / offer）回流，用 **Pearson r** 检验
   「这个匹配分到底准不准」——准就继续信、不准就反过来用真实数据修权重。

差异化一句话：**匹配分是可被证伪的**。市面上的匹配工具要么黑盒打分，要么只做一次单向匹配
就结束，永远不告诉你「它说你很匹配，你到底有没有收到面试」。career-loop 用一条能让用户自己复现的
相关系数，直接回答这个问题——这恰好对应大厂 JD 里反复出现的「建立效果评估体系、用数据验证产品表现」。

能力词表分四层叠加、覆盖 **69 个岗位族 / 180 个能力项**（AI / 技术、通用能力、各行各业岗位族、
职业分类骨架），词表外的要求按文本相似度兜底、不丢弃。核心只用 Python 标准库，**零依赖**；
浏览器 Demo 是单文件 HTML + 原生 JS，无需安装、数据不上传；也可 `pip install -e .` 后用命令行全链路
（匹配 → 记录投递 → 回流 → 校准）。已提供 60 条**控制回归集**（合成边界集，明确非真实标注声明）与 231 个单测，CI 跑通；另有公开 HF 集的真实端到端验证（族识别 93.6%（英文）/ 86.0%（中文）/ 混合模式 93.4% / r=0.193）。

- **创意与场景价值（35）**：把「求职匹配」从一次性黑盒打分升级成「可证伪 / 可校准」闭环，
  切中应届生盲投焦虑，理念本身就是 AI PM / 数据产品的最小实践。
- **作品完成度（40）**：CLI 16 个子命令全链路可用；单文件网页 Demo 真在浏览器里算分；
  231 个单测 + CI；60 条控制回归集（合成边界集，**不做"真实标注"夸大**）；公开 HF 集真实端到端验证（族识别 93.6%（英文）/ 86.0%（中文）/ LLM 混合模式 93.4% / r=0.193）；2 分 15 秒旁白演示视频；`scripts/demo_cli.py` 一键离线演示；岗位族识别带**可选 LLM 后端**（1,838 条真实调用实测，规则与模型盲区互补，weak 族 service 52%→78%）。

## 7. GitHub Pages 部署
仓库根 `.gitignore` 已排除个人数据；`docs/` 即站点根：

**方式 A（推荐，一条命令）**——在能访问 github.com 的网络下：
```bash
bash scripts/publish_github.sh
```
脚本会依次做：网络体检（github.com 可达性 + DNS 污染诊断）→ 本地体检（工作区干净 /
密钥扫描 / 站点根就绪）→ 认证检查（gh CLI 或 `GH_TOKEN`）→ 创建 public 仓库 →
推送 `main` → 开启 Pages（来源 `main` / `/docs`）→ 访问自检。
凭证只从 `gh auth login` 或环境变量读取，**不写入任何文件、不打印**。

**方式 B（手动）**
1. GitHub 仓库 → Settings → Pages → Source: Deploy from a branch → Branch: `main`, Folder: `/docs`。
2. 约 1 分钟后访问 `https://jian935.github.io/career-loop/`。
3. 校验：链接能打开、og-cover.png 正常加载、分享到社交平台能出富预览卡片。
