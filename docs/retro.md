# career-loop 造物复盘：一个「反焦虑」求职匹配工具，是怎么被真实数据打脸、又变诚实的

> 参加 1024 造物挑战的作品复盘。这篇不是产品说明书，是一个工具从「我觉得很准」到「真实数据说你不准」的全过程。

---

## 0. 太长不看

我做了一個求职匹配工具 career-loop：你贴 JD + 简历，它给你一个匹配分、一张逐项能力矩阵、和「补哪一项涨分最多」的建议。

但它最不一样的地方是——**匹配分可以被你自己证伪**：你拿去投递，把真实结果（已读 / 面试 / offer）回填，它会用相关系数 r 告诉你「之前那个分到底准不准」。准就继续信，不准就用真实数据反过来修。

真实数据给了我两记耳光，也给了我两枚勋章：

- 公开数据集（1,167 条真实 JD）上，岗位族识别 **93.6%**，引擎分 ↔ 真实标注 **r = 0.193**（弱正相关，规则基线的真实水位）。
- 我自己的 **40 条真实投递**上，r = **-0.059**（早期互动口径，几乎不相关）。这个匹配分预测不了 HR 理不理我。

后者很难看，但我选择把它写进产品的「证据墙」公开出来。**一个敢公开自己失效区间的工具，才配说「可证伪」。**

---

## 1. 缘起：求职季的伪问题

求职季最折磨人的不是投不出去，是**盲投**。

同一个「我会 Python / 我做过 Agent」，在十个 JD 里含金量完全不同。市面上的匹配工具给你一个分数就结束，永远不会告诉你：它说你「很匹配」的那次，你到底有没有收到面试。

我想要的不是一个更花哨的分数，而是一个能回答这个问题的最小闭环：

> **这个匹配分，到底能不能预测 recruiter 理不理我？**

如果回答不了，那它和「星座运势」没区别。

---

## 2. 核心主张：匹配分必须可被证伪

这是整个项目唯一的「创意内核」，也是我和其他求职工具划清界限的地方。

普通工具的逻辑是：`JD + 简历 → 分数`。单向、黑盒、不可回头验证。

career-loop 的逻辑是：`JD + 简历 → 分数 →（你真实投递）→ 真实结果 → 相关系数 r → 校准`。

关键在最后两步：**让分数接受真实世界的审判**。这恰好对应大厂 JD 里反复出现的那句话——「建立效果评估体系，用数据验证产品表现」。我把它做成了一个应届生也能跑的最小实践。

---

## 3. 技术方案三件套（都是笨办法，但可复现）

**① 分层能力词表（66 岗位族 / 171 能力项）**
四层叠加：AI/技术硬词 + 通用能力 + 各行各业岗位族 + 职业分类骨架。词表外的要求按文本相似度兜底，不丢弃。

**② 关键词覆盖率匹配（规则基线，零依赖）**
核心只用 Python 标准库。把 JD 拆成能力项，逐条比对简历里的证据词，加权算出匹配分。没有模型、没有 API Key，所以任何人都能在自己电脑上复现。

**③ 校准闭环（apply → log → calibrate）**
- `apply`：自动算预测匹配分并记录投递；
- `log`：回填真实状态；
- `calibrate`：按分数桶算正反馈率，和真实结果求 Pearson r，给一个诚实的 verdict。

## 4. 真刀真枪的检验（最关键的章节）

### 4.1 公开数据集：它「大致对」
我用了 HuggingFace 上一个公开的 job-resume 数据集（1,167 条 JD、9,544 份简历、122,560 个配对，CC BY、零隐私）。

- **岗位族识别准确率 93.6%**（1092/1167）：金融 96.6%、HR 99.5%、商务拓展 100%、IT 93.3%，销售 78.4%（v0.8.7 用真实数据补判别词，从 69.8% 提上来）。
- **引擎分 ↔ 真实标注 r = 0.193**（2,000 对抽样）。方向对、正相关，但解释力有限——这正是纯规则基线的真实水位，我不往高了吹。

散点图和复现脚本都开源了，任何人能一键跑出来。

### 4.2 我自己的 40 条真实投递：它「预测不了」
我把**自己的真实简历 + 真实 JD + 真实投递结果**喂进去。结果：

- **r = -0.059**（早期互动口径：HR 沟通/感兴趣/初筛通过/面试邀约算正反馈，n=40，正反馈 7 条 17.5%）。不是强负相关，是**几乎没有预测力**。
- 分桶看更耐人寻味：20–40 分档正反馈率 30%、40–60 档 27.3%，而我投得最多的 **60–80 分档 15 条零正反馈**——我以为「最匹配」的区间，恰恰是零反响区间。

**根因：关键词覆盖率匹配分在我身上「饱和」了。** 我的简历覆盖了几乎所有 AI PM 要求，多数 JD 直接算成 100%，分数挤在高位、区分度归零，「高分」并不代表 HR 更想理我。

这反倒是个真结论：**当前这套规则匹配分，不能预测「HR 会不会理你」**，至少对我个人这个高覆盖样本无效。

### 4.3 为什么故意公开这个丑数
很多项目只晒好看的指标。我把 r=-0.059 写进 `evidence.md` 和网页「证据墙」，只出聚合数字、不含任何简历/公司名。

> 口径说明：40 条这批记录只有早期平台信号、没有终局 offer/拒信，所以对外引用的是 early 口径；
> 引擎修复后的重算值会更新（本文数字为 2026-10-25 当前引擎值），复现命令见文末。

理由很朴素：**一个只敢晒优点的工具，没资格说自己「可证伪」。** 公开失效区间，反而让「可证伪」从口号变成肉眼可见的证据——这也是它最该被点赞的地方。

## 5. 踩坑与诚实边界

- **英文 JD 直接打分会退化。** 英文 JD × 中文简历直接抽需求，只抽得出 3–4 项、全算 100%。必须忠实翻译成中文（同一内容换引擎母语）才能正确抽取。英文原文保留供审计。
- **匹配分饱和。** 规则覆盖率匹配对高覆盖样本会失去区分力：分数全挤在高位，「高分」不再等于「更想理你」。这是算法局限，不是 bug，要写进边界说明。
- **早期信号 ≠ 终局录取。** 那 40 条是「投递当天 HR 是否理你」的早期漏斗，不是 offer/拒信。校准回答的是「能否预测早期互动」，不是「能否预测录取」。

## 6. 数据教我的真实求职建议（不是工具教的，是数据教的）

从那 40 条硬数据里，我学到比工具更值钱的东西：

- **7/40 = 17.5% 的正反馈，全部集中在 AIGC / 创作者方向**（aigc 6/17、generative 1/2）；**大模型应用方向 13 条 0 正反馈**。
- 结论很直接：**押注 AIGC / 创作者方向**（我有真实项目贴得住），大模型应用要么补一个可信技术项目、要么降优先级。
- 另一批样例数据（不同岗位族、带终局结果）里，最大的漏斗在简历关，但**过半拒绝是 HC 冻结 / 招满 / 院校批次等市场因素，不可控**——别把每次拒绝都归因于自己。

---

## 7. 给想「造物」的人的清单

- **先想清楚「凭什么信你」。** 我的创意内核一句话就是「可证伪」，整个闭环都围绕它转。
- **用公开数据打地基。** 真实数据集比自己编的样例有说服力一万倍，而且零隐私风险。
- **敢公开失效区间。** 这是信任的放大器，不是减分项。
- **零依赖 > 大模型炫技。** 一个 `pip install -e .` 就能跑、不用 API Key 的工具，评委/用户试起来门槛最低。
- **数据隔离是底线。** 个人简历、真实投递结果永远不进公开仓库（`.gitignore` 排除），只出聚合统计。

## 8. 打脸之后：又发生了什么（W7–W10）

复盘不是终点。被真实数据打脸之后，项目又走了四步，每一步都用公开数据验收：

**① 把中文啃下来（族识别 77.8% → 86.0%）。** 英文数据 93.6% 不能说明中文也行。换了 1,838 条真实中文 JD 重测，第一版只有 77.8%。诊断发现 96.6% 的未命中是**错判**不是漏判，根因是招聘站的来源声明和反诈免责声明被当成了 JD 正文——**先剥数据伪影、再修词表**，最后用 dev/hold-out 双层拆分证明增益不是过拟合。

**② 把「补不动」也做成证据。** 最弱的客服/项目管理两族，单词、短语、语境约束、人工过目四条路全试完，确认补不动——增益上限是「能救回的漏判数」，而那两族的漏判大半是数据集自身的标题-正文矛盾。**试过但没做到的，和做到的一样上墙。**

**③ 规则 + LLM 混合，86.0% → 93.4%。** 纯词表到顶之后加了可选 LLM 后端（1,838 条真实调用实测）。关键发现：**两个引擎的盲区几乎不重叠**——规则漏短 JD 和同义表达，LLM 漏咨询/实施/售前类；混合后 service 族 52%→78%、project_mgmt 70%→83%。LLM 单独用不是替代品，但排序放在规则前面（blend）比简单并集高 16 个百分点 top-1 准确率。

**④ 主链路永远不接 LLM。** 匹配分、校准 r 必须离线可复现，所以 LLM 只做族识别这个「可选后端」，没 Key 就自动回退规则、行为与旧版逐字节一致。**可证伪的底线是不让任何不可复现的东西进核心链路。**
